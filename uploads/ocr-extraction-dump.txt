Robin Dock — OCR / Extraction (Office Tier)
Requirements spec — session output for architecture handoff to Fable. Model-agnostic.
Purpose | Specify the OCR + content-extraction capability that defines the Office tier ($149/location). Office is where Robin Dock crosses the deterministic-trust line on purpose: it reads document content. Everything here is checked against the governing principle below.
Governing principle | Extraction PROPOSES; humans and deterministic rules DISPOSE. AI output is always a reviewable suggestion with visible provenance — never a silent mutation of identity, patient-binding, or the record.
Push rule (thesis) | The AI never pushes to PIMS. Completion makes a track ELIGIBLE. A human push (single or bulk) executes it. Completion authorizes; the push acts; the AI never does either.
Two-pass model | Pass 1 CLASSIFICATION runs only on cold/untyped docs deterministic routing couldn't type (drains Missing Doc Type). Pass 2 FIELD+PATIENT EXTRACTION runs on EVERY typed doc regardless of how it was typed. Two separately-triggered, separately-costed operations.
Trust ladder | Per-field-class auto-write eligibility, gated by BOTH a confidence threshold AND deterministic validation. Doc-type can auto-apply at high confidence; fields auto-populate above threshold / leave empty below; patient-binding is suggest-only in v1; nothing reaches PIMS without human completion.
Counter-positioning | vs. Documo/Valerie (auto-write-to-record on confident branch). Robin Dock's divergence: the confident branch still proposes. Review/confirmation is the design center for anything touching identity, patient-binding, or the record — not just the exception path.
Status of zones | A / B / C / E / F LOCKED. D delivered as an output contract (write-back mechanics are a separate parked session). See per-zone tabs.
Cadence note | Locked decisions in green. Parked / open items in amber (see Parked tab). Cross-session hand-offs on the Cross-Session tab.

Zone A — Extraction Scope (what gets read and pulled)
ID | Feature | Decision (LOCKED) | Notes / consequences
A1 | Content-based doc-typing | Reads cold/untyped fax → proposes doc-type. High-confidence classification MAY auto-apply (reversible, low-harm, drains Missing Doc Type). Low/med confidence lands as a suggestion. | The only capability allowed to auto-apply on day one. Pass-1 operation; runs only on docs deterministic routing couldn't type.
A2 | Field extraction (per doc-type schema) | Extract per-doc-type field schema on EVERY typed doc. Identity fields (patient name, client/owner) held to highest threshold + validation gate; non-identity fields auto-populate above threshold / empty below. | Pass-2 operation; runs regardless of how the doc was typed. v1 = Tier-1 full extraction (see Doc-Type Grid). Tier-2 fast-follow.
A3 | Patient/contact match (suggest-only v1) | Suggest-only in v1. Requires >=2 agreeing corroborating keys to be high-confidence-eligible; single key (e.g. name alone) is always low-confidence. Hard conflict (e.g. species mismatch) VETOES regardless of score. Ambiguous match surfaces ranked candidates, never auto-picks. No-match surfaces 'create new?' (never auto-creates). | Highest-harm error class. Contact-history tie (see A3b) is a strong corroborating key. Preserves locked 'Complete without confirmed match'.
A3b | Contact↔patient tie (match key + card tab) | A confirmed association between a contact and patients they've historically sent docs about. Counts as a STRONG corroborating key toward the >=2-key rule. Surfaced bidirectionally on a dedicated TAB (connected patients on the contact; connected contacts on the patient). Built from confirmed matches; inspectable + correctable. | Deterministic asset (exchange history) makes AI patient-match safer — cross-tier value chain. Weak early, strengthens as practice confirms (earn-into-it). A wrong tie must not silently poison future matches.
A4 | Multi-type detection | Propose BOTH tags when a doc carries two types (e.g. referral containing labs). Each type is an independent suggestion with its own confidence and its own per-tag completion track. | Operational payoff of 'folders are filters, not bins'. Mixed states on one doc are fine (e.g. Referral auto-applied, Lab suggested).
A4b | Post-completion reconciliation loop | At FULL doc completion, compare AI-proposed types vs. final human-confirmed types. The delta is the calibration signal (accuracy logging). Runs at full completion only, not per-tag. | Feeds per-practice accuracy mapping. MUST stay in a separate lane from the deterministic 7-15-20 engine (no double-suggest). Manual typing of an extraction-failed doc is the highest-value correction signal.
A5 | Confidence signal | Every extraction carries confidence, surfaced plain-language (high/med/low, never a raw 0.87). Confidence is PER-FIELD and PER-CLASSIFICATION, not per-document. Must map to MEASURED per-practice accuracy, not raw model score (calibration). | Engine must record confirmations/corrections from day one to build the calibration mapping, even before it uses it to auto-flow.
A6 | Second-pass targeting (cost) | CLASSIFICATION runs strictly on the Missing-Doc-Type-bound (cold) docs, automatically at arrival as the fallback branch of deterministic routing — before a human sees it. FIELD extraction runs on every typed doc. | Do NOT spend model cost second-guessing a deterministic route's TYPE. But field/patient extraction is universal — it's the core value and must run even on deterministically-typed docs.
A7 | Junk / spam classification | AI may SUGGEST junk/spam; human confirms. Never auto-applies spam (misclassifying a real referral as spam is high-harm). | Routes to existing bulk-spam machinery on confirm.
=== xl/worksheets/sheet3.xml ===
Zone B — Trust Surface & Threshold Architecture
ID | Item | Decision (LOCKED) | Notes
B1 | Auto-write eligibility ladder | Per-field-class behavior. Doc-type: auto-apply eligible above classification threshold, else suggested. Non-identity fields: auto-populate above extraction threshold, else empty. Patient-binding: suggest-only v1 (highest threshold + validation gate). Clinical values / PIMS write: staged. | Two INDEPENDENT thresholds — classification vs. extraction.
B2 | Below-threshold behavior | Leave-empty / staged, never applied (industry standard). The record is never briefly wrong. Human provides the value during the confirm pass. | Chosen over fill-then-flag/undo.
B3 | Validation gate (v1) | A field must pass BOTH its confidence threshold AND a deterministic validation check to be auto-apply eligible. Patient-match specifically requires 'unambiguous matching record exists'. Validation failure forces review regardless of model confidence. | Cheap deterministic logic; on-brand. Lets autonomy be safely raised later.
B4 | Required-field-missing trigger | If a required field for a doc-type can't be extracted, the doc goes to review even if everything else cleared. | Independent of confidence (MuleSoft rule).
B5 | Provenance — field level | Each extracted field shows a lightweight marker (AI-extracted + plain-language confidence); clicking reveals the source region on the doc. | Inspectable like route-reason. Design owns exact treatment.
B6 | Provenance — History level | Extraction logs ONE event ('System extracted, model X, N fields, confidences') — not one entry per field. Each CORRECTION logs its own entry with old→new value, user, timestamp. History is append-only / tamper-evident. | Matches Documo 'Info & History' + Docsumo event model. Corrections double as the calibration signal.
B7 | Correction application | Corrections apply INSTANTLY to the doc, but only influence FUTURE extraction via the calibration layer's periodic recompute — never a live per-correction model change. | The 'no silent black-box drift' guarantee.
B8 | Per-doc-type tuning affordance | Ship conservative defaults; expose a plain-language per-doc-type dial (Documo-style slider) for admins. No per-field numeric exposure in v1. Range: from 'stage everything for this type' up to 'auto-apply the eligible classes' — never past the identity/clinical carve-out floor. | 'Turn auto-apply off for a type' = the slider at its most conservative end. Carve-outs are floors the slider can't cross.
B9 | Calibration posture | Plain-language high/med/low must map to measured per-practice accuracy. Defaults start conservative (lean 'stage it'); autonomy is justified by accumulated confirmation/correction data. | Why auto-write is earned, not day-one — no calibration data yet at activation.
Auto-write eligibility matrix
Field class | Above threshold + valid | Below threshold OR fails validation
Doc-type classification | Auto-apply tag (confirmed) | Stays SUGGESTED, pending confirm
Non-identity fields (dates, test names, referring clinic) | Auto-populate | Left EMPTY, staged for reconciliation
Patient-binding | Suggest-only v1 (highest threshold + 'unambiguous match exists' gate) | Suggest-only, flagged
Clinical values / PIMS write | Staged; push earned per-doc-type after calibration | Staged

Zone C — Reconciliation with Locked Models (status & routing)
ID | Item | Decision (LOCKED) | Notes
C1 | Extraction feeds the existing funnel | AI-suggested type flows through the SAME deterministic folder-filter routing as a deterministic type. Extraction feeds the top of the funnel; it never gets its own routing path. Single routing spine. | Keeps the deterministic spine authoritative.
C2 | Suggested vs. confirmed doc-type | An unconfirmed AI type is a distinct SUGGESTED object, structurally separate from a confirmed type. It does NOT create per-tag completion work until promoted. Promotion (human confirm OR high-confidence auto-apply) writes permanent identity. Dismissing a suggestion is NOT a tag-strip (stripping stays classification-correction only). | Prevents polluting permanent, never-stripped identity. High-confidence auto-apply writes CONFIRMED directly (skips suggested → not in review).
C3 | Processing happens at arrival | Classify + extract + patient-match all run at arrival, BEFORE a human opens the doc. The doc lands unread, already processed. 'Needs review' is not a mid-stream flag. | Corrects earlier over-engineered 'review flag' model.
C4 | Review signal = unread | Because processing completes at arrival, UNREAD remains the review signal (as in Organize). No separate review-flag state reintroduced. What's pre-populated vs. empty is shown ON the doc, not as a queue state. | The confirm-and-complete pass IS the work surface (Valerie-screenshot shape: doc left, fields right).
C5 | Inbox row status = 4-state aggregate | Inbox shows a document-level rollup: In Review → (review done) → Not Started → In Progress → Complete. In Review = AI extracted, needs help/manual. Not Started = review done, no workflow item begun. In Progress = >=1 workflow item open. Complete = all tracks done. | Inbox is unfiltered → can't resolve a single track → must aggregate.
C6 | Folders = filters (Gmail model) | A folder is a saved filter that can match one or many doc-types (e.g. Admin = Labs+Records+Billing). A doc lives once and surfaces in every matching folder. Never a bin; never duplicated. | Confirmed against 'folders are filters, not bins'.
C7 | Folder status = per-track, scoped | In a folder, a row shows a rich status chip for EACH of the doc's tracks that the folder's filter matches (not other tracks). Single-track-in-view → one rich status. The filter that admits the doc selects which chips show. | A doc in Admin because it's Lab+Records shows Lab + Records status here, not its Referral status.
C8 | Multi-track display = accordion | Multi-type doc collapses to a parent row showing the 4-state aggregate; expands to one child row per in-folder-matching track, each with its own rich status. Single-type docs don't expand. Completed tracks grey out; active ones colored. | Parent = aggregate; child = rich. Resolves multi-status without forking the doc or duplicating rows.
C8b | Accordion rules | Aggregate at parent, rich at child. Filter/sort operate on CHILD tracks (a parent surfaces if any in-folder child matches). Children shown = only tracks matching this folder's filter. Accordion exists in FOLDERS only; inbox stays flat aggregate. | Design owns density/treatment.
C9 | typed ≠ completed | Auto-typing (even high-confidence) creates a track a human must still complete. Auto-apply speeds SETUP; completion (and thus push-eligibility) always has a human. Architectural rule. | The seam where 'AI drains the pile' and 'human gates the PIMS' coexist.

Zone D — PIMS Output Contract (write-back mechanics are PARKED)
This session defines only the clean payload write-back consumes. The AI never pushes. Completion → eligible. Human push (single/bulk) executes.
ID | Item | Decision (LOCKED as contract) | Notes
D1 | One payload per doc-type TRACK | A confirmed extraction payload is emitted per doc-type track when THAT track reaches confirmed/complete — not one bundled per-document payload. A Referral+Lab doc emits two payloads independently. | Matches per-tag completion. Avoids forcing both tracks to finish before anything can write back.
D2 | Payload carries per-field provenance (audit only) | Each field carries value + confidence + source region + confirmation-state (human-confirmed / auto-applied / left-empty). This provenance is for AUDIT/History, NOT a write-back gate. | The completion gate — not a per-field label — is the safety mechanism (see D5).
D3 | Emit / eligibility timing | The payload becomes AVAILABLE (eligible) at track completion. Whether it is pushed then, batched, or synced later is the write-back session's call. | Data ready the moment its own track is done, regardless of sibling tracks.
D4 | Push trigger (v1 rule) | Manual, human-triggered push (Documo model). Single (from detail page) AND bulk (select multiple eligible items). Scheduled/daily sync is PARKED as a future setting. The AI never pushes. | Bulk operates ONLY on eligible (completed, not-yet-pushed) tracks — the eligibility gate doubles as the bulk-select filter.
D5 | Completion gate = the safeguard | Nothing pushes unless its track is COMPLETE, and completion requires a human. So anything eligible to push has been human-reviewed by construction. Even a future auto-sync is safe: it only sweeps completed (=human-cleared) tracks. | 'The AI never pushes; completion pushes; completion is always human.'
D6 | Payload envelope | Document identity (doc ID, source, arrival ts, page count, source-PDF link); confirmed doc-type; patient binding (record ref OR null — Complete-without-match is valid — plus human-confirmed vs high-confidence-auto flag); extracted fields (per D2); provenance envelope (model version, extraction ts, calibration snapshot ref); workflow completion state (track, final status, who, when); eligibility/push-state (eligible; downstream pushed/not-yet-pushed). | Contract shape for Fable + the write-back session.

Zone E — Failure Modes, Cost, Latency
ID | Item | Decision (LOCKED) | Notes
E1 | Unreadable / low-quality faxes | Extraction degrades gracefully, never makes a doc worse than Organize. Garbage scan → lands untyped (or partial), human does the work. Partial extraction is valid (extract legible pages, leave rest empty). Confidence collapses naturally → nothing auto-applies → safe path. | Office is never worse than Organize on a bad fax; at worst equal.
E1b | Legibility pre-screen | A cheap legibility check gates the expensive extraction call. A black/noise page fails the screen and lands untyped WITHOUT burning a full model call. | Cost control on exactly the docs that would waste spend.
E2 | Latency / async UX (greyed-out model) | Doc appears in the list on arrival but GREYED-OUT / not-yet-actionable until extraction completes or fails. No mid-process work access (prevents hand-typing into a doc about to auto-populate). No verbose 'Reading/Extracting' status vocabulary — greyed-out IS the signal. No per-doc cancel. | Matches Documo/Docsumo (Processing → Review). Extraction is usually seconds, so grey flickers by; it only lingers on genuinely slow docs (big records PDF), which is exactly when the signal is wanted.
E2b | Failure resolution | On failure the greyed state lifts and the doc becomes a normal workable untyped doc (UNREADABLE / FAILED / PARTIAL·PAGE-CAP inherited from inbox pipeline states). | Graceful degradation to the Organize baseline.
E3 | Run-once | Extraction runs one time at arrival. Re-extraction ONLY on explicit human trigger (e.g. a cleaner copy arrives), never automatically. | Cost discipline + avoids silently re-processing a doc someone already worked.
E4 | Cost model | Classification cost bounded (cold docs only). Field-extraction cost = real per-doc spend, runs on every typed doc — the cost line that justifies the $149 tier. Legibility pre-screen trims waste. | Volume/overage exposure noted for pricing (parked, not this spec).
E5 | Push modes | Manual single + bulk (see D4). Bulk needs an eligibility filter/view ('Completed — ready to push'). Partial-failure handling & per-track-vs-per-doc bulk selection PARKED to write-back session. |
